What this actually is

A router and a memory layer

If you use Claude Code in more than three folders, you already have this problem: a session in one folder makes a decision that matters in another, and the other folder never finds out. This template fixes that with two ideas and about eight files.

One place to open Claude from

The org root holds links to the folders you already have. On Windows those are junctions; on macOS and Linux, symlinks. Nothing is moved, renamed or copied, and deleting a link never touches its target.

Because a session starts here, it always loads the same CLAUDE.md, sees the same department map, and reaches every connector from one .mcp.json.

One ledger per department

Every department has a file in state/: scoreboard, what is in flight, a context bank of facts sessions keep needing, a friction queue, and a dated log.

The rule is read before, append after. A session that changes something and writes nothing has thrown that context away, and the next one starts cold.

Cross-references are the point

When work in one department changes something in another, /log writes a line in both. That single habit is what stops the failure this whole thing exists to prevent.

/review then hunts for cross-references nobody acted on. Those matter more than stalled tasks, because no one owns them.

Five commands and two agents

The daily loop

Skills live in .claude/skills/ and work the moment you open Claude at the org root. Nothing to install.

/brief <dept>Starting workReads the brief and the ledger, reports what is in flight, and flags anything the ledger claims that the filesystem now contradicts.

Choices worth knowing about

Why it is built this way

Deliberate

Links, not a merge

Moving your folders into one root would break every hardcoded path in your hooks, per-repo configs and scripts. Links cost nothing to abandon: delete the org folder and everything you own is exactly where it was.

Deliberate

Markdown, not a database

At a few thousand notes, ripgrep is exact and instant and files are read natively with no pipeline in between. Markdown is diffable, hand-editable, and outlives the tool that wrote it.

A vector store adds a service to run and a way for notes to go stale silently. Add one when a product needs retrieval at runtime, not for personal recall.

Know this

Search will not follow the links

Ripgrep does not descend into junctions or symlinks. A search from the org root returns nothing from your vaults, which looks like an empty folder rather than a broken search.

Name the scope instead: rg "term" vaults/notes. Reading, editing and globbing through a link path all work normally. npm run doctor reminds you.

Know this

Ledgers are never overwritten

Re-running npm run init regenerates briefs and the dashboard but will not touch a file in state/, not even with --force. Your memory is safe from your own tooling.

Not included

No automation that writes for you

There is no hook that silently appends to a ledger. An entry written by a machine that did not do the work is noise, and noise in the memory layer is worse than a gap.

The habit is the product. The tooling only makes it one command.

Gaps are first class

Anything marked gap in the config is drawn in gold on the map, listed in its brief, and ranked by /review. Most org charts only show what exists, which is exactly the half you already know.

Getting started

Four steps

Needs Node 18 or newer and Claude Code. Works on Windows, macOS and Linux.

  1. Use this template, then clone it

    Click "Use this template" on GitHub, or clone directly. Everything you need ships in the repo; there are no dependencies to install.git clone <your-copy> && cd company-brain

  2. Edit one file

    org.config.json. Point roots at folders you already have, then rename the departments to match how you actually think about your work. Mark the things that do not exist yet as gap; those are the useful entries.Start from examples/ if the default four do not fit.

  3. Build it

    Creates the links, writes a brief and a ledger per department, generates the dashboard and the launcher. Run it as often as you like: it never overwrites a ledger.npm run init && npm run doctor

  4. Open Claude from the root

    Use the generated launcher rather than opening Claude inside individual project folders. That is the whole mechanism. Then /brief before work and /log after, until it stops feeling like a chore.Open-Org.cmd on Windows, ./open-org.sh elsewhere

Being straight about it

What this does not solve

It cannot make you write the entry

Every mechanism here assumes you run /log. If you do not, this is a folder of empty templates and a nice picture. The honest test is whether the ledgers have entries a month from now.

The map drifts unless you sync

Briefs are generated once from your config and then go stale as you move things. npm run sync catches paths that no longer exist, but it cannot tell you that a department's purpose changed.

It is not multiplayer

Ledgers are plain markdown with no locking, so two people appending at once will conflict. For a team, put the org root in a private repo and treat ledger edits like code.
