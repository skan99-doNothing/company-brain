# The company brain

This is the single place to open Claude from. Everything is reachable from here through
`vaults/`, which holds links to your real folders. Nothing was moved or copied. A link is a
pointer: deleting one never touches its target.

Read `HOME.md` for the department table and what is linked. Read `org.config.json` for the
machine-readable version of the same thing.

## The one rule that makes this work

**Read the department ledger before you start. Append to it before you finish.**

Ledgers live in `state/<department>.md`. They are the memory. A session that changes
something and does not write a line to the ledger has thrown that context away, and the
next session starts cold. This is the whole reason this folder exists.

Order of operations for any substantive request:

1. Work out which department owns it. Read `HOME.md` if you do not already know.
2. Read `departments/<dept>.md` for the paths, then `state/<dept>.md` for what is in flight.
3. Do the work in the real folder, through `vaults/`.
4. Append a dated line to `state/<dept>.md` under `## Log`.
5. If the work touched a second department, append one line to that department's
   `## Cross-references`. This is the step that stops work in one folder from being
   invisible in another.
6. If a choice was made that would be expensive to reverse, append to `decisions.md`.

Skip step 4 only when the session changed nothing: a question answered, a file read.

## Searching through the links

Ripgrep does not follow directory links, so a recursive search started at this root will
**not** descend into `vaults/`. That is a feature: it stops every casual search from
touching tens of thousands of files. It does mean you must name the scope.

```
rg "term" .                  # finds nothing in your vaults
rg "term" vaults/notes       # right
rg "term" vaults/code/myapp  # better
```

Reading, editing and globbing through a link path all work normally. Only root-level
recursive search is affected.

Beyond that: start narrow. Search the specific project folder named in the department brief
first, and widen only if it comes back empty. If a linked vault carries its own `.ignore`
excluding cold storage, that still applies through the link, so leave it alone.

## Writing rules

- Never move, rename or delete anything inside `vaults/`. Those are real folders reached
  through links. Create and edit in place. Reorganising is a separate, explicit request.
- New files go where the owning department's brief says they go, not into this root.
- This root holds routing, ledgers and tooling. It is not a document store.
- Dates in filenames and log lines are `YYYY-MM-DD`.

## Generated files

`departments/*.md`, `HOME.md` and `.mcp.json` are generated from `org.config.json` by
`npm run init`. Editing them by hand works and they will be left alone on the next run,
but the config is the source of truth. `state/inventory.json` is generated by
`npm run sync` and is always overwritten; never hand-edit it.

`state/*.md` is never generated over. Those are yours.

## Tooling

- `/route` decides which department owns a piece of work.
- `/brief` opens a department: reads its brief and ledger, reports what is in flight.
- `/log` appends a ledger entry, mirrors friction, cross-references other departments.
- `/review` walks every ledger and produces a digest.
- `/sync` rescans the filesystem and reports paths that no longer exist.

Agents live in `.claude/agents/`. Connectors are consolidated in `.mcp.json` at this root,
generated from the `mcpServers` block in `org.config.json`, so a session started here has
every connector the individual folders had.

## Prose

Briefs, ledger entries and reports are prose written for a person. Keep them plain and
specific. Do not invent numbers: if a figure is needed and the session did not produce it,
leave it out or ask.
